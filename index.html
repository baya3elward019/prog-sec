  • Debug = OFF
  • Encryption = ON
  • No Default Password
  • Admin Access Restricted

Pattern: [a-zA-Z0-9_]{3,20} Allowlist Validation
Comparison

Allowlist vs Denylist

✗ Denylist

«امنع ما أعرفه»

if "script" in input:
    reject()
# Bypass: <SCRIPT>, <img src=x onerror=...>

يمكن تجاوزها بصيغة غير متوقعة.

✓ Allowlist

«اسمح فقط بما أعرف أنه صحيح»

import re
if not re.fullmatch(r"[a-z0-9_]{3,20}", input):
    reject()
# فقط النمط المعروف يُقبل

الأسلوب المفضل: Allowlist

Error Semantics

Fail Open vs Fail Secure

FAIL OPEN
Error ↓ Access Granted ✗ 
except Exception:
    return True
FAIL SECURE
Error ↓ Access Denied ✓ 
except DatabaseError:
    log_incident()
    return False
Logging

تسجيل الأحداث

✓ يُسجّل

  • Successful login
  • Failed login
  • Access denied
  • Permission changes
  • Repeated validation failures
  • Time / User / Source

✗ لا يُسجّل

  • Passwords
  • Session tokens
  • Card numbers
  • Sensitive personal data

Secrets Management

إدارة الأسرار

config.py — git 
DB_PASSWORD = "Admin@2024"
⚠ SECRET LEAKED
• لا تكتب الأسرار داخل الكود.
• لا ترفع ملفات الإعداد التي تحتوي أسرارًا إلى Git.
• أقل صلاحية ممكنة.
• غيّر السر دوريًا وفور الاشتباه بتسربه.
